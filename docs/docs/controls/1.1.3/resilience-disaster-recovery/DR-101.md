# DR-101: Recovery source is independent of primary failure domain

**Catalog version:** 1.1.3  
**Domain:** Resilience & Disaster Recovery  
**Severity:** critical  
**Maturity stage:** Mature  
**Well-Architected mapping:** Scalability, Resiliency, Efficiency, Disaster Recovery, Modularity, Interoperability, Simplicity, Observability

## Objective

Establish and verify the organizational practice: recovery source is independent of primary failure domain.

## Requirement

Recovery source is independent of primary failure domain.

## Risk

Material security, availability or compliance exposure.

## Evidence sources

- **Source:** `Architecture evidence`
  - **Fields:** `independence`
  - **Evidence key:** `dr.failure_domain`

## Evaluation logic

**Mode:** `manual_or_hybrid`

Evaluate collected evidence for `independence` against the stated requirement; distinguish missing evidence from a failing control.

## Expected result

PASS when the requirement is demonstrably satisfied; PARTIAL when implementation is incomplete; FAIL when materially absent; NOT ASSESSED when evidence is unavailable; N/A only with documented rationale.

## Exception criteria

A documented, approved exception with owner, rationale, compensating control and expiry.

## Remediation guidance

Remediate the identified gap for: Recovery source is independent of primary failure domain. Assign an accountable owner and target date.

## Maturity-stage basis

Organizationally established, standardized or governed practice aligned to the GitHub Well-Architected Mature stage.
